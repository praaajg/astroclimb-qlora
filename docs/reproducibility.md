# Reproducibility guide

## Implementation status

The paper's Appendix A states that the original repository contains **no
training or preprocessing scripts, no prompt file, and no split-index file**.
This repository is an independent, clean-room implementation reconstructed from
the paper's protocol. It is intended to make the method auditable and
extensible; it is not the authors' original competition code. The paper's
reported numbers are preserved in [`results/`](../results) and are not
regenerated by this code by default.

## Environment

| Component | Recommended |
|---|---|
| Python | 3.10–3.12 |
| CUDA | 12.1+ |
| Training GPU | 1× NVIDIA A100 80 GB (paper) |
| Inference GPU | 2× NVIDIA T4 (paper, Kaggle) |
| Core packages | `transformers`, `peft`, `accelerate`, `bitsandbytes`, `torch` |
| CPU-only utilities | `numpy`, `pandas`, `Pillow`, `scikit-learn`, `PyYAML` |

Install the CPU-testable package first:

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

Then install the GPU stack:

```bash
pip install -e ".[train]"
```

`bitsandbytes` is excluded on macOS in `pyproject.toml`; 4-bit training
therefore requires Linux or Windows with a supported NVIDIA GPU.

## 1. Data

Download the public competition release:

```bash
python scripts/download_data.py --output data/raw
```

Expected files include a training CSV and a test CSV. The loader validates the
following schema (column names are configurable in `configs/qlora.yaml`):

| Column | Required | Description |
|---|---|---|
| `id` | No | Pair identifier; generated if absent. |
| `object_a` | Yes | Base64 image bytes, an image path, or caption text. |
| `object_b` | Yes | Base64 image bytes, an image path, or caption text. |
| `label` | Train only | One of the four relation labels. |
| `type_a` | No | `figure` or `caption`; inferred when absent. |
| `type_b` | No | `figure` or `caption`; inferred when absent. |

If the released CSV uses different column names, update the `data:` block in
`configs/qlora.yaml` or pass a custom configuration file. Do not rename the
label values; the parser and metric code use the paper's four class names.

The official test labels are not used during training, model selection, or
prompt design.

## 2. Reproduce the validation split

The split uses seed 42, 450 examples per class, and original row indices with
zero overlap:

```python
from astroclimb.data import load_pairs
from astroclimb.split import stratified_validation_split

frame = load_pairs("data/raw/train.csv")
train, validation = stratified_validation_split(frame, n_per_class=450, seed=42)
print(len(train), len(validation))  # 8200 1800
```

The paper notes that figures, captions, or source papers may recur across
splits. Validation therefore measures **in-distribution pair generalization**,
not generalization to unseen papers.

## 3. Training

```bash
astroclimb-train --config configs/qlora.yaml
```

| Paper setting | Repository setting |
|---|---|
| Backbone `google/gemma-4-E4B-it` | `model.id` |
| 4-bit NF4, double quantization, bf16 compute | `model.load_in_4bit`, `quant_type`, `double_quant`, `compute_dtype` |
| LoRA r=64, α=128, dropout 0.05 | `lora.r`, `lora.alpha`, `lora.dropout` |
| Attention + MLP projections | `lora.target_modules` |
| 8,200 training rows | Generated by `split.py` |
| LR 1e-4, cosine, 5% warmup (204 steps) | `training.learning_rate`, `scheduler`, `warmup_steps` |
| Per-device batch 2 × grad accumulation 8 | `per_device_train_batch_size`, `gradient_accumulation_steps` |
| Max sequence length 1,536 | Dataset/processor truncation; set in config |
| Max 2,560 steps | `training.max_steps` |
| Eval every 200 steps, patience 3, threshold 0.001 | `eval_steps`, `early_stopping_*` |
| Greedy decoding, 32 new tokens | `inference.max_new_tokens`, `do_sample` |

The paper reports the best validation loss at step 1,000 (`0.3464`) and
early-stopping termination at step 1,600. Runtime depends on GPU, driver, and
`transformers` version; the original run used one A100 80 GB.

### Prompt masking

The paper describes appending the true label after the prompt for supervised
fine-tuning but does not specify whether prompt tokens are masked from the
loss. The reference config therefore defaults to `mask_prompt_tokens: false`.
Set it to `true` for the more common response-only objective. This is an
explicit reconstruction choice, not a claim about the original code.

## 4. Inference

```bash
astroclimb-infer \
  --config configs/qlora.yaml \
  --input data/raw/test.csv \
  --adapter ShivRamSaud/gemma4-e4b-qlora-astroclimb-v2-fresh \
  --output outputs/test_predictions.csv
```

The output has one row per input pair and one-hot columns in this exact order:
`same_figure`, `same_paper`, `related_papers`, `unrelated_papers`.

The released adapter also contains a `submission/` folder with the original
scored 10,000-row predictions. Use it to verify that your inference pipeline
produces comparable class counts before running a full job.

## 5. Evaluation

```bash
astroclimb-evaluate \
  --gold data/raw/labels.csv \
  --pred outputs/test_predictions.csv \
  --output outputs/metrics.json
```

The evaluation reports macro F1, accuracy, per-class precision/recall/F1, and
the confusion matrix. `--gold` needs an `id` and `label` column; `--pred` needs
an `id` plus either a `prediction` column or all four one-hot columns.

## Expected numbers

| Setting | Macro F1 | Accuracy |
|---|---:|---:|
| Gemma-4-E4B zero-shot, validation | 0.4408 | 0.5206 |
| Submitted adapter, validation | 0.5347 | 0.5483 |
| Submitted adapter, official test | **0.64282** | — |

Per-class validation F1 is `same_figure 0.5705`, `same_paper 0.5311`,
`related_papers 0.3508`, `unrelated_papers 0.6864`.

## Fidelity and limitations

- The exact system prompt is reproduced verbatim; the chat template is applied
  by the model processor rather than hard-coded.
- The seed-42 split and 450-per-class validation size are reproduced exactly.
- Image resize (448×448) and caption truncation (2,000 characters) follow the
  paper.
- The original training script is unavailable. Collator details, prompt
  masking, and mixed-precision edge cases may differ.
- The paper reports no caption-only or image-only ablations, so multimodal
  gains cannot be separated from textual topic similarity.
- Several baseline runs cover only partial row subsets (397, 445, or 610
  pairs); their scores are not comparable to full-split runs.
- The adapter was trained for 1,600 steps with early stopping; the best
  checkpoint is step 1,000. Reimplementation may select a different step.

## Reproduction checklist

- [ ] Data downloaded from the official Kaggle release.
- [ ] Label names and pair types match the expected schema.
- [ ] Split sizes are exactly 8,200 / 1,800 with 450 examples per class.
- [ ] Zero-shot Gemma-4-E4B scores near 0.4408 validation macro F1.
- [ ] Fine-tuned adapter reaches roughly 0.53 validation macro F1.
- [ ] Test predictions use all four labels and one-hot column order.
- [ ] Evaluation is run on the official test labels only after submission.
